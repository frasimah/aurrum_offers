## Связь со сделками Twenty

Разобрано по живой базе 07.09.2026: 128 сделок, объект `opportunity`.

**Связь уже существует — руками.** В сделке есть поле `specifikaciyaFile`,
и там лежат ровно наши файлы, оба формата:

```
4021-Offer-20260618-HENGE-FREEDOM-NAT.pdf
4069-Offer-20260728-PORADA-MARO-NAT.xlsx
0000-Offer-20260903-DECASTELLI-ELE.pdf
```

Разбор имени: `<номер сделки>-Offer-<дата>-<БРЕНД>-<ПРОЕКТ>-<владелец>`.
Первое число — это поле `name` сделки. `0000` — заглушка «номера ещё
нет»; так же назван и наш образец `0000-Offer-20260725-AUR-FORM.xlsx`.
Суффикс — владелец сделки: NAT = Наталья Титова, ELE = Елена Клепикова
(сверено по `ownerId`).

**Что в сделке уже есть под нашу задачу:**

| Поле сделки | Куда ложится у нас |
|---|---|
| `name` | номер спецификации в шапке и в имени файла |
| `stage` = `KP_I_SPECIFIKACIYA` | этап, на котором наш инструмент и нужен |
| `companyId`, `pointOfContactId` | «Покупатель» в шапке |
| `sposobOplaty` (нал / безнал / B2B) | уровень цены — сейчас менеджер выбирает руками |
| `tipKlienta` (архитектор / конечный / B2B) | дизайнерская наценка |
| `ownerId` | суффикс имени файла |
| `amount` (EUR) | итог предложения |
| `specifikaciyaFile` | куда класть готовый файл |
| `dogovorFile`, `closeDate` | «Договор» и «Дата» в шапке |

**Как разложить по риску:**

1. **Только чтение: выбрать сделку — шапка заполняется сама.** Номер,
   покупатель, договор, дата; способ оплаты подставляет нужный уровень
   цены, тип клиента — наценку. Ничего не пишем, риска нет.
2. **Правильное имя файла** вместо `0000-...` — вычисляется целиком из
   сделки.
3. **Запись обратно:** класть файл в `specifikaciyaFile`, обновлять
   `amount`. Только после первых двух и только по явной кнопке, никогда
   автоматически.

**Что нужно, чтобы начать:** токен API Twenty в переменных окружения
(добавляете сами, я его не набираю). **Не проверено:** есть ли у Twenty
пригодный эндпойнт загрузки файла в поле — от этого зависит только
третий шаг, первые два от него не зависят.

## Габариты

**Porada: 58 товаров, где размеры только чертежом.** Техлиста у них нет
вовсе, а чертёж — SVG на самой странице
(`div.characteristics_dimensioni_img_w img[src]`), где текст переведён в
кривые: тега `<text>` нет ни в одном из 58, регуляркой не прочитать.

Путь проверен: svglib + reportlab переводят SVG в PDF чистым Python
(на Vercel пойдёт), 58 из 58 конвертируются, числа сохраняются —
сверено глазами по растру Vera Sofa: 186 / 96 / 82.

Три вещи закрыть до внедрения:
1. `_dims_grounded` сверяет габариты с текстом страницы, а чисел с
   чертежа в тексте нет — прочитанное сотрётся молча. Помечать такие
   габариты как не-со-страницы, ровно как это сделано для техлиста.
2. Часть чертежей — листы СЕМЕЙСТВА: «180 ~ 300 x 100-110-120-130 x 73.5».
   Даже при идеальном чтении габаритов не дают, и это правильно.
3. Имена файлов бывают с двойным расширением `.svg.svg` — адрес брать из
   атрибута, а не регуляркой.

**Нотация не несёт диапазонов.** В описание уходит `31x31x125`, а книга
пишет `D25/31x125Н`: у торшера диаметр меняется по высоте, и буква `D`
говорит, что предмет круглый. То же у кровати — `202x241x36/92Н`, 36 в
ногах и 92 у изголовья. Три числа этого не держат: чтобы вернуть, разбор
должен нести по оси диапазон и признак «диаметр», а объём продолжать
считать по одному числу. Сперва замерить, у скольких карточек нотация
правда расходится.

**Пять товаров Porada без размеров нигде** — agea, cuna-lounge-pouf,
enook, killian-testata-xl, rhode. На странице нет даже блока размеров.
Останутся пустыми, и это честно.

**Техлист подставляется без проверки, что он про этот товар.** У Versace
La Medusa в карточку уехали габариты низкой тумбы. Проверять совпадение
модели в документе с моделью карточки.

**`_dims_disagree` не вызывается нигде.** Функция сверки габаритов из
двух источников написана и мертва.

## Извлечение

**Нет повтора и отступа на 429 от Google.** Сегодня любой отказ по
квоте считается отказом модели и уводит на запасной путь. Проявилось
дважды: при параллельных прогонах и когда кончились кредиты.

**Ответ модели нестабилен.** Rucellai: один прогон вернул пустую строку
размеров, следующий — верную «92,5x47x83». Тот же адрес, тот же код.
Эскалация на тяжёлую сработала и всё равно вернула пусто. Свойство
поставщика, а не наш дефект, но менеджер должен знать, что повтор
разбора иногда помогает.

**Код отделки извлекается, но не печатается** — «T010», «M11+M07».

**Файлы указаний написаны только для двух сайтов** из восьми:
`config/brands/porada.it.md` и `config/brands/luxurylivinggroup.com.md`.
Остальным (henge07.com, venicem.com, barovier.com, emmemobili.it,
fendicasa.com, longhi.it) добавка не достаётся — работают на общем
промпте.
